# Quality Gate Skill

## When to Activate
- After implementing a software feature or fix (post senior-engineer)
- After generating a document, presentation, or research paper
- Before committing or delivering any artifact to the user
- When explicitly asked to "verify", "review", or "QA" a result
- When a previous task ended without explicit verification

---

## Inputs Required
- Artifact type: code / PPTX / document / web page / data file
- Project root path (for code artifacts)
- Output file path(s)
- Test / build / lint commands (auto-detect if unspecified)

---

## Gate 1 — File Existence Check (all artifact types)

For every output file claimed to exist:
1. Run `view_file` or `dir` / `ls` to confirm the path is real.
2. Check file size > 0 bytes.
3. Record: EXISTS / MISSING / ZERO-BYTES.

**Block delivery if any output is MISSING or ZERO-BYTES.**

---

## Gate 2 — Code Artifact Checks

Run in this order; stop on first failing gate and fix before continuing:

### 2a — Build
```
<build-command>   # e.g. npm run build, go build ./..., python -m py_compile
```
- PASS: zero exit code, no ERROR lines in output.
- FAIL: read full error; isolate; fix; re-run.

### 2b — Lint / Style
```
<lint-command>    # e.g. eslint ., pylint src/, golangci-lint run
```
- PASS: zero new lint errors introduced by this change.
- Pre-existing errors must be documented, not silently ignored.

### 2c — Type Check
```
<typecheck-command>   # e.g. tsc --noEmit, mypy src/, pyright
```
- PASS: no new type errors.

### 2d — Unit / Integration Tests
```
<test-command>    # e.g. npm test, pytest -v, go test ./...
```
- Record: total tests, passed, failed, skipped.
- PASS: 0 failures, 0 errors.
- If tests are absent: state NOT RUN — tests absent. Do not claim PASS.

### 2e — Security Spot-Check
Grep the changed files for:
```
grep_search: (password|secret|api_key|token|private_key) in changed files
```
- Any hardcoded secret = BLOCK + alert user.
- Check for SQL string concatenation, shell injection, unescaped output.

---

## Gate 3 — Document / Presentation Artifact Checks

For PPTX / PDF / LaTeX / Markdown documents:

1. **Structural check**: Confirm slide count or section count matches the approved outline.
2. **Content spot-check**: Read 3 random sections; confirm content matches the source material.
3. **Citation check** (research documents): Verify at least 3 references appear in the
   bibliography and were previously marked VERIFIED in the research-lab workflow.
4. **Editable format**: For PPTX — confirm the file was generated by a script (PptxGenJS /
   python-pptx), not exported as a flat image deck.
5. **Visual consistency check** (if browser tool available): Open the file; screenshot;
   confirm fonts, colours, and layout are consistent.

---

## Gate 4 — Web / UI Artifact Checks

1. Open the page in the browser subagent.
2. Check: page loads without console errors, no broken images, responsive at 1280px width.
3. Check: all interactive elements have IDs; forms submit correctly; navigation works.
4. Take a screenshot and embed it in the report.
5. State: VERIFIED (visually confirmed) or ASSUMED (not opened).

---

## Gate 5 — Regression Check

If Git is available:
```
git diff --name-only HEAD
```
- Confirm only files listed in the implementation plan were modified.
- Any unintended file modification = ALERT user before delivery.

## Quality Gate Report Template

```
QUALITY GATE REPORT
===================
Artifact: <name and path>
Date: <timestamp>

GATE 1 — File Existence
  <file>: EXISTS | MISSING | ZERO-BYTES  [<size>]

GATE 2 — Code Checks (if applicable)
  Build:      PASS | FAIL | SKIPPED
  Lint:       PASS | FAIL | SKIPPED  [new errors: N]
  Type-check: PASS | FAIL | SKIPPED
  Tests:      PASS | FAIL | NOT RUN  [passed/total]
  Security:   PASS | ISSUE FOUND | SKIPPED

GATE 3 — Document Checks (if applicable)
  Structure:  PASS | FAIL
  Content:    PASS | FAIL
  Citations:  PASS | FAIL | N/A
  Editable:   YES | NO

GATE 4 — Web/UI (if applicable)
  Page loads: PASS | FAIL | NOT CHECKED
  Screenshot: <embedded or path>

GATE 5 — Regression
  Unintended files modified: NONE | <list>

OVERALL VERDICT: PASS | FAIL | CONDITIONAL PASS
Conditions (if any): <list>
Recommended follow-up: <list or NONE>
```

---

## Failure Handling

| Situation | Action |
|---|---|
| File missing | Re-run the generation step; do not mark as delivered |
| Test failures | Fix before reporting PASS |
| Security issue found | BLOCK delivery; alert user with exact location |
| Unintended files modified | Alert user; revert if safe |
| Gate tool unavailable | Mark gate SKIPPED with reason; do not mark PASS |

---

## Completion Criteria

- All applicable gates attempted
- Verdict is explicit: PASS / FAIL / CONDITIONAL PASS
- No gate is marked PASS without being actually executed
- Report delivered to user before artifact is handed off
